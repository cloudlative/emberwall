You do not have to start from scratch. Emberwall can read an existing firewall configuration, turn it into a project, and build it for any target.

## Supported formats

| Format | Paste the output of |
|---|---|
| iptables-save | `iptables-save`, `ip6tables-save`, or both one after the other |
| nft list ruleset | `nft list ruleset` |
| ufw commands / status | ufw commands (`ufw allow ...`), `ufw show added`, or `ufw status` |
| firewalld zone XML | a zone file such as `/etc/firewalld/zones/public.xml` |

For iptables, Emberwall tells IPv4 and IPv6 apart by the `# Generated by ip6tables-save` header line, so keep the headers when you paste both.

## Import a configuration

1. Open **Import / export** in the sidebar (under *Library*).
2. Under **Import an existing firewall**, paste the ruleset. **Paste sample** fills in an example if you want to try it first.
3. Leave **Import format** on **Detect automatically**, or pick the format.
4. Press **Preview import**. The preview shows how many rules were imported and lists every skipped line with the reason.
5. Press **Replace project with import** to open it as the current project. Undo brings the previous project back.

![Import and export page](shot:transfer)

Parsing happens in the page; nothing is uploaded.

## What the importers do

- **Default policies** of the built-in chains (for example `:INPUT DROP`) become the project's default policies.
- **Baseline rules** that only restate a built-in option are folded into the option instead of becoming rules: accept on `lo` becomes **Loopback**, accept established/related becomes **Established connections**, drop invalid becomes **Drop invalid**.
- **NAT rules** for masquerade, source NAT and port forwards are imported where their shape is supported.
- **Comments** on rules become the rule names, so rulesets generated by Emberwall come back with their original names.

## What is skipped

Importers cover the common rule shapes. Anything unusual is listed as skipped with a reason, never guessed. Common reasons:

- negated matches (`!`);
- custom chains and jumps to them;
- options or targets the importer does not know;
- tables other than filter and nat (iptables), and chains that are not base filter chains (nftables);
- NAT rule shapes that are not supported;
- protocols other than the ones Emberwall models;
- ufw application profiles (`app`);
- firewalld services outside a built-in list, and zone bindings (`<interface>`, `<source>`), which are not rules. Model them as an Emberwall [zone](doc:objects-and-zones#zones) if you need them.

The firewalld importer knows these services: `ssh`, `http`, `https`, `dns`, `ntp`, `smtp`, `smtps`, `imaps`, `mysql`, `postgresql`, `cockpit`, `dhcpv6-client`, `mdns`, `wireguard`, `kube-apiserver`, `samba`, `nfs` and `redis`. For any other service, add its ports by hand.

> [!TIP]
> Review the skipped list carefully. A skipped rule is not in the project, so the imported ruleset may allow or block differently from the original. Use the [simulator](doc:simulator) and [reachability matrix](doc:reachability-and-topology) to check the result.

## Migrate from iptables to nftables

1. On the server, save the current rules:

   ```sh
   sudo iptables-save > rules.v4
   sudo ip6tables-save > rules.v6
   ```

2. Paste both files into **Import an existing firewall**, preview and replace the project.
3. Read the skipped list and recreate anything important by hand.
4. Run the **Audit** and add [policy tests](doc:policy-tests) for the access that must not change.
5. Select the nftables target for the server.
6. Open **Compare** to see the old and new output side by side. For example, compare the server's iptables version with its nftables version.
7. Build and apply with `emberwall-apply.sh`, then make the rules permanent. See [Build output](doc:build-output).

> [!WARNING]
> Emberwall's nftables output replaces only its own table, `inet emberwall`. Rules loaded through iptables stay in the kernel and keep filtering: a packet has to be accepted by every table. Remove the old iptables rules and stop loading them at boot once the new ruleset is confirmed.

On distributions where `iptables` is iptables-nft, iptables rules already live in the kernel's nftables and show up in `nft list ruleset`.

The same steps work between any two tools, for example from ufw to firewalld.

## Import from a live server

In [server mode](doc:server-mode), the **Live server** page reads the running firewall over SSH and runs the same importers. **Adopt as project** opens the result as the current project. See [Live servers](doc:live-servers).

## Export and open project files

The **Project file** panel on the same page saves and loads the whole project as JSON. See [Workspace](doc:workspace#import-and-export-json) and [Project file format](doc:project-format).
